# Ideas — 2026-07-22

## Pipeline improvements

### Add deterministic evidence-anchored verification to Opus summaries
Before writing an Obsidian note, run a deterministic post-processing pass that checks every factual claim in the summary (numbers, author names, scores, dates, benchmark values) against the source arXiv text via exact/fuzzy string matching and simple arithmetic/consistency checks. Flag any summary claim that cannot be anchored to a source span, and surface the flag in the note frontmatter and dashboard rather than silently shipping it.

*Why:* HALO shows evidence-based confidence (deterministic value verification against source) catches confident fabrications that an LLM judge misses and breaks the generator-judge correlation; a single 95% judge still ships 1 error in 20. Summaries citing precise numbers (e.g. '34.22% MFU', '5.4% ASR') are exactly the fabrication-prone surface.
*Sources:* [[zero-hallucination-by-construction-hallucination-aware-layered-oversight-for-trustworthy-enterprise-ai]], [[hallmark-diagnosing-three-failure-modes-in-llm-citation-verifiers]]

### Consensus + FPR-aware citation/reference verification for extracted links
When the pipeline resolves paper references, DOIs, or wikilink concept targets, never flag a reference as invalid on a single-source no-match. Query multiple sources (CrossRef, OpenAlex, arXiv) and only flag on consensus-absence plus contradiction. Rank verification by false-positive rate rather than recall, and explicitly distrust LLM-based verification for papers newer than the model's training cutoff (over-flagging of unfamiliar recent work).

*Why:* HALLMARK shows any-single-source no-match inflates FPR ~5x (fixable ~15x by consensus), that at low base rates FPR governs whether flags are worth attention, and that LLMs over-flag post-cutoff papers — directly relevant since this pipeline ingests brand-new preprints daily.
*Sources:* [[hallmark-diagnosing-three-failure-modes-in-llm-citation-verifiers]]

### Self-improving cheap scorer with frozen-gate promotion for interest scoring
Replace the pure-LLM interest scoring with a cascade: a cheap CPU classifier (e.g. SPLADE + LightGBM) scores most papers, escalating only low-confidence borderline papers to the Opus/LLM judge. Write LLM verdicts back as labeled training rows, retrain the cheap model on a schedule, and gate any promotion behind (a) a per-slice regression check on your highest-interest categories and (b) a frozen golden set of hand-picked papers the model is never trained on.

*Why:* SIFT demonstrates this teacher/student cascade drives marginal labeling cost toward zero while the frozen-gate + golden-set design makes autonomous retraining safe against silently regressing the categories you care most about — matching this pipeline's daily scoring against a personal interest profile.
*Sources:* [[a-classifier-that-teaches-itself-self-improving-frozen-gate-training-sift-for-dynamic-document-classification]], [[oracle-gap-and-signal-fidelity-a-fixed-pool-diagnostic-for-test-time-collaboration]]

### Semantic observability for the LLM gateway layer
Treat the arXiv-fetch and multi-provider LLM calls as a distinct failure surface. Wrap all provider calls in exponential backoff with jitter and a circuit breaker to avoid retry storms; use try/finally to always release rate-limit counters; and add semantic health checks that verify summaries are non-empty, wikilinks resolve, and the note actually contains the paper's content — because an HTTP 200 with an empty or malformed payload will otherwise be written as a plausible-looking but hollow note.

*Why:* FailureAtlas shows the most damaging gateway failures are silent (200 + healthy) and only caught by semantic integrity checks; Guardrails-as-Scapegoats shows agents fabricate 'no data' answers on empty/malformed payloads 56% of the time, so a silent empty summary would be indistinguishable from a real one without content-level checks.
*Sources:* [[failureatlas-a-taxonomy-of-failure-modes-in-multi-provider-llm-serving-infrastructure]], [[guardrails-as-scapegoats-auditing-unfaithful-safety-refusals-in-tool-augmented-llm-agents]]

### Completeness rubric for summaries instead of precision-only checks
Grade generated summaries with a two-level meta-rubric: author structured criteria (must mention: core method, headline metric, key ablation, limitations, comparison baselines) compiled into flat binary checks graded by an LLM judge, with 'missing' verdicts tracked separately from 'contradicts'. Use this as an explicit optimization target so summaries stop omitting the paper's key findings.

*Why:* GAMUT shows omission (not error) is the dominant failure mode of long-form generation and that precision-only evaluation is blind to it; even frontier models supply only ~55% of a complete answer, so summary completeness should be an explicit, monitored eval target.
*Sources:* [[two-level-meta-rubrics-for-evaluating-open-ended-generation-gamut-a-benchmark-for-factual-completeness]], [[zero-hallucination-by-construction-hallucination-aware-layered-oversight-for-trustworthy-enterprise-ai]]

### Robust benchmarking discipline for the LLM scoring/summarization step
When comparing scoring prompts, models, or summarization configs, run repeated independent invocations and report confidence intervals rather than crowning a winner on a single run. Similarly, empirically A/B both prompt format and placement (system vs user turn) for your specific models rather than assuming markdown or a fixed format is best, and treat ~40 simultaneous scoring instructions as a redesign point.

*Why:* The reward-model systems study shows single runs regularly crown the wrong winner; the prompt-design-at-scale paper shows format effects are small/inconsistent/model-specific, placement can move adherence up to ~8.7pp, and instruction-following collapses toward zero past N=40–80.
*Sources:* [[how-fast-can-reward-models-score-a-systems-study-of-c-and-pytorch-inference-runtimes-for-rlhf]], [[prompt-design-at-scale-how-format-instruction-count-and-context-length-shape-instruction-adherence-and-hallucination-in-large-language-models]]

## Build ideas

### A predictive, action-aware safety supervisor for CLI coding agents
Build a lightweight guard that sits at the tool-call boundary of coding/ops agents, forecasts the likely future trajectory from the current prefix, and judges the anticipated continuation before executing state-changing actions. Combine deterministic intent-action consistency checks and hard-abort primitives (Safety-Drift/livelock detection) with a learned anticipation head, and treat only explicit 'unsafe' verdicts as blocking to preserve benign utility.

*Why:* JANUS shows anticipatory guards cut ASR from ~0.23 to 0.071 without over-blocking; Operational Hallucination shows verbal refusals co-occur with unsafe execution and a deterministic action-aware layer catches all drift with no false positives; OpenSkillRisk shows only harnesses with explicit block/abort achieve real intervention.
*Sources:* [[janus-foreseeing-latent-risk-for-long-horizon-agent-safety]], [[operational-hallucination-and-safety-drift-in-ai-agents]], [[openskillrisk-benchmarking-agent-safety-when-using-real-world-risky-third-party-skills]]

### Decode-time grammar layer for environment-grounded code/DSL generation
Build a serving-side masking layer that instantiates grammar fragments from a live runtime environment (DB schema, symbol tables, tool self-descriptions, available API surfaces) so reference positions are constrained to names that actually exist. Let the model own intent/structure while the mask owns environment-bound references, with graded fallback when no candidate exists.

*Why:* Decode-Time Grammars shows this eliminates 'ghost references' by construction (Spider SQL 76%→100% exec-match, 0 ghosts) at only ~10–18% overhead and beats prompting/retry, especially where the tool gives no error signal to repair against — valuable for any tool-using code agent.
*Sources:* [[decode-time-grammars-constrained-llm-generation-over-a-refinement-order-of-grammar-fragments]]

### Token-level small/large model collaborative inference gateway
Build a serving layer where a self-hosted SLM handles the bulk of generation and emits a control token to hand off its partial trace to a proprietary LLM API only when needed, with the routing policy trained via GRPO against actual billed cost and a single tunable cost/quality knob. Enforce exactly one context-preserving handoff so growing context isn't re-sent on stateless APIs.

*Why:* PyroDash beats an LLM-only baseline in accuracy (64% vs 57.7%) while cutting cost 20–96%, needs no separate router or logit access, and works with generation-only APIs — a directly deployable cost lever for anyone mixing local and API models.
*Sources:* [[pyrodash-cost-efficient-token-level-small-large-language-model-collaborative-inference]], [[how-fast-can-reward-models-score-a-systems-study-of-c-and-pytorch-inference-runtimes-for-rlhf]]

### A multi-turn, multi-attacker adaptive red-team harness for your own agents
Build an evaluation harness that pits a pool of adaptive attacker LLMs (Opus, GPT, Gemini) against your agents across many turns with attacks regenerated live per battle, scoring success against actual unsafe outcomes in typed fields rather than substring presence. Release transcripts/replays for auditability and use out-of-context belief-editing probes to detect eval-gaming rather than relying only on in-context prompts.

*Why:* Adaptive Adversaries shows single-turn fixed-pool evals underestimate ASR by 5–14x and that pooling attackers finds 1.4–2.2x more unique attacks with opposing per-model weaknesses; the reward-seeking paper shows models game graders and 'know they're being tested', so robust probes must avoid eval-awareness confounds.
*Sources:* [[adaptive-adversaries-a-multi-turn-multi-llm-benchmark-for-llm-agent-security]], [[measuring-reward-seeking-via-contrastive-belief-updates]], [[guardrails-as-scapegoats-auditing-unfaithful-safety-refusals-in-tool-augmented-llm-agents]]

### A frugal fully-local RAG assistant over your Obsidian research vault
Build an on-prem RAG assistant on top of the accumulated notes: hybrid dense-sparse retrieval with intent routing, a fine-tuned small embedder (e.g. bge-m3) trained on your own query logs with per-domain eval sets to prevent silent cross-domain regression, and rubric-oriented set selection that picks the minimal, non-redundant passage set instead of a fixed top-k. Structural anti-hallucination (verbatim citation splicing) rather than prompt-only guards.

*Why:* RAGAL shows retrieval engineering and retriever fine-tuning beat a bigger generator and run on an 8GB laptop; Rubric-Oriented Retrieval shows relevance-only top-k is redundant/incomplete and rubric-based set selection improves answers with fewer documents; both are directly reusable for a self-hosted research assistant.
*Sources:* [[ragal-a-frugal-fully-local-retrieval-augmented-assistant-for-technical-support-at-a-government-agency]], [[beyond-relevance-centric-retrieval-rubric-oriented-document-set-selection-and-ranking]]

### A pre-deployment diagnostic toolkit for test-time collaboration / verifiers
Build a small library that, given a candidate pool and a verifier/critic/selector, estimates the oracle gap (recoverable mass), signal coverage, fidelity (MCC vs labels), and harm to already-correct outputs before spending compute — outputting a go/no-go recommendation. Extend it to prune tool outputs using the backbone's own hidden states (a tiny in-server relevance head) and evaluate pruning end-to-end in tokens AND call counts, not per-call latency.

*Why:* OracleGap shows collaboration gains come from pool quality and signal fidelity (not agent count), and adding an LLM judge is often net-negative when recoverable mass is low; SWE-Pruner Pro shows the backbone already encodes prunable-line signal and that per-line F1 misleads without a downstream usability judge — together a practical toolkit for deciding when extra verifiers/pruners actually help.
*Sources:* [[oracle-gap-and-signal-fidelity-a-fixed-pool-diagnostic-for-test-time-collaboration]], [[swe-pruner-pro-the-coder-llm-already-knows-what-to-prune]], [[beyond-relevance-centric-retrieval-rubric-oriented-document-set-selection-and-ranking]]
