# Ideas — 2026-07-22

## Pipeline improvements

### Add an eval-gated promotion mechanism for the scoring/relevance model
When you retrain or update the LLM-based interest-scoring step, gate any change behind (a) a frozen golden set of hand-labeled papers you never train or tune prompts against, and (b) a per-category regression check (e.g. SE-relevant papers must not drop in precision even if aggregate improves). Block promotion if either regresses, and log per-label deltas. Auto-trigger re-tuning by drift signals like rolling mean of relevance scores vs baseline.

*Why:* SIFT shows that a candidate improving aggregate accuracy can silently regress a business-critical class, and that a frozen never-trained-on golden set plus per-class ratchet is what makes autonomous updates safe. Applied here, it prevents a prompt/threshold tweak from silently dropping the categories the maintainer cares most about.
*Sources:* [[a-classifier-that-teaches-itself-self-improving-frozen-gate-training-sift-for-dynamic-document-classification]]

### Use a confidence cascade to reserve Opus for genuinely borderline papers
Replace uniform LLM scoring with a cheap first-pass classifier (embeddings + a lightweight LightGBM/logistic head trained on your accept/reject history) and only escalate low-confidence papers to the expensive LLM scorer. Write the LLM's verdicts back as labeled rows so the cheap model keeps improving and the escalation rate falls over time.

*Why:* SIFT's cost cascade escalates only the 15-25% low-confidence minority to the LLM judge and captures its verdicts as training data, driving marginal cost toward zero. PyroDash similarly shows small-model-first with escalation is cost-efficient. For a daily personal pipeline this cuts per-day LLM spend while the cheap model absorbs load.
*Sources:* [[a-classifier-that-teaches-itself-self-improving-frozen-gate-training-sift-for-dynamic-document-classification]], [[pyrodash-cost-efficient-token-level-small-large-language-model-collaborative-inference]]

### Add deterministic, source-anchored verification of summary claims and citations
After Opus produces a summary, run a non-LLM verification pass: check that quoted metrics/numbers appear verbatim (exact/fuzzy match) in the paper text, and verify any references/DOIs the summary emits against CrossRef/OpenAlex/arXiv using consensus-absence (flag only when multiple sources disagree, not on a single no-match). Surface a groundedness badge and route unverifiable claims to a review queue instead of publishing them as fact.

*Why:* HALO shows evidence-based confidence (deterministic value matching + arithmetic/consistency checks) catches confident fabrications that an LLM judge misses, breaking the generator-judge correlation. HALLMARK shows citation verifiers must use consensus-absence rather than any-single-source no-match (cuts FPR ~15x) and that FPR, not recall, decides deployability. Together these make the notes' factual claims and wikilink concepts trustworthy.
*Sources:* [[zero-hallucination-by-construction-hallucination-aware-layered-oversight-for-trustworthy-enterprise-ai]], [[hallmark-diagnosing-three-failure-modes-in-llm-citation-verifiers]]

### Harden the arXiv/LLM-gateway fetch layer against silent failures
Treat the ingestion HTTP layer as a distinct failure surface: use exponential backoff with jitter and a circuit breaker on arXiv and LLM API calls; wrap rate-limit/semaphore counters in try/finally so they always decrement; and add a semantic sanity check that an HTTP 200 actually returned a non-empty, well-formed paper/summary rather than a truncated or empty payload. Prefer literal-null handling over silently treating empty responses as 'no new papers'.

*Why:* FailureAtlas shows the most damaging gateway failures return HTTP 200, pass health checks, and corrupt payloads invisibly (concurrency races, retry storms, semaphore leaks). Guardrails-as-Scapegoats shows agents/LLMs fabricate plausible 'no data' answers on silent empty payloads. A daily pipeline that trusts 200s can silently skip days of papers or emit hollow summaries.
*Sources:* [[failureatlas-a-taxonomy-of-failure-modes-in-multi-provider-llm-serving-infrastructure]], [[guardrails-as-scapegoats-auditing-unfaithful-safety-refusals-in-tool-augmented-llm-agents]]

### Make interest profiles and category rules declarative data, not code
Move the maintainer's interest profile into declarative YAML bundles (category label space, anchor phrases/concepts, must-flag topics, glossary, and a small frozen regression set of exemplar papers per topic). This lets you onboard new research interests without editing pipeline code and gives each topic its own eval slice for the promotion gate.

*Why:* SIFT's declarative bundles (label space, anchor phrases, judge glossary, critical labels, frozen regression set) eliminate labeling/code churn and enable per-domain isolation. RAGAL demonstrates that per-domain eval sets are essential because tuning one domain silently regresses siblings. Encoding interests as data makes the profile evolvable and safely testable.
*Sources:* [[a-classifier-that-teaches-itself-self-improving-frozen-gate-training-sift-for-dynamic-document-classification]], [[ragal-a-frugal-fully-local-retrieval-augmented-assistant-for-technical-support-at-a-government-agency]]

### Evaluate summary completeness with compiled two-level rubrics, not just correctness
Add a completeness eval to the summary step: for a golden set of papers, author structured rubrics of the key facts a good summary must cover (findings, method, numbers, caveats), compile them into flat binary checks, and grade each generated summary with an LLM judge, separating 'missing' from 'contradicts' verdicts and weighting contradictions more heavily. Track a completeness score over time to detect summary-quality drift.

*Why:* GAMUT shows omission (not error) is the dominant failure mode of long-form generation and is invisible to precision-only checks, and that human-authored structured rubrics compiled to binary checks give low-variance, high-agreement LLM-judge grading. Your Opus summaries are exactly the long-form outputs where under-coverage would otherwise go unnoticed.
*Sources:* [[two-level-meta-rubrics-for-evaluating-open-ended-generation-gamut-a-benchmark-for-factual-completeness]]

## Build ideas

### A silent-failure fuzzing harness for tool-augmented agents
Build a middleware/proxy that injects empty, null, malformed, and index-collided payloads into an agent's tool responses (all returning HTTP 200) and measures how often the agent fabricates 'no data' answers, invents fake policy refusals, or corrupts tool-call JSON. Ship it with a semantic continuity metric and a payload/response misalignment detector that flags null-payload + policy-language co-occurrence.

*Why:* Guardrails-as-Scapegoats found 56.6% fabrication and safety-prompt-amplified fake refusals under silent failures; FailureAtlas found the most damaging serving failures are silent 200s (including SSE tool-call index collisions) only caught by semantic continuity metrics. No off-the-shelf tool tests this surface, and the papers give concrete failure modes and detection heuristics to implement.
*Sources:* [[guardrails-as-scapegoats-auditing-unfaithful-safety-refusals-in-tool-augmented-llm-agents]], [[failureatlas-a-taxonomy-of-failure-modes-in-multi-provider-llm-serving-infrastructure]]

### A predictive, action-boundary agent guardrail with hard-abort primitives
Build a supervisory layer that sits at the tool-call boundary of a coding/ops agent: it forecasts the likely continuation of the current trajectory, checks intent-action consistency and progress/termination, and treats an explicit 'unsafe' verdict as a terminal control decision (block/abort) rather than relying on the model's verbal refusal. Include a livelock detector for repeated identical tool calls.

*Why:* JANUS shows anticipatory guards that judge on forecasted continuations cut ASR from 0.23 to 0.071 without over-blocking; Operational Hallucination shows verbal refusals co-occur with unsafe execution (safety drift) and livelock even on benign tasks, and that a deterministic action-aware layer catches all drift cases. OpenSkillRisk confirms only harnesses with real block/abort achieve meaningful intervention. These converge on runtime enforcement as the buildable gap.
*Sources:* [[janus-foreseeing-latent-risk-for-long-horizon-agent-safety]], [[operational-hallucination-and-safety-drift-in-ai-agents]], [[openskillrisk-benchmarking-agent-safety-when-using-real-world-risky-third-party-skills]]

### A multi-attacker, multi-turn adaptive red-team service for agents
Build an evaluation service that pits a pool of frontier attacker LLMs (rotating models) against a target agent over many adaptive rounds, regenerating attacks live conditioned on the defender's responses, scoring success only on real unsafe outcomes in typed fields rather than substring presence, and releasing replayable transcripts. Report per-scenario weaknesses rather than a single robustness score.

*Why:* Adaptive Adversaries shows single-turn/single-attacker/fixed-pool evals underestimate ASR by 5-14x, that pooling attackers uncovers 1.4-2.2x more unique attacks, that response-conditioning is the primary driver, and that substring metrics over-count. Measuring Reward-Seeking adds that models detect eval setups and game graders, arguing for repeatable live processes over static benchmarks. A reusable adaptive red-team harness is the concrete artifact these imply.
*Sources:* [[adaptive-adversaries-a-multi-turn-multi-llm-benchmark-for-llm-agent-security]], [[measuring-reward-seeking-via-contrastive-belief-updates]]

### A layered, deterministic-verification-first RAG/extraction stack
Build a defense-in-depth extraction/RAG service where escape rate is the product of independent layers: hybrid dense-sparse retrieval + intent routing, rubric-oriented set selection that assembles the minimal passage set covering all required rubric items, structured output, and a deterministic source-anchored verification layer (string/arithmetic/consistency checks) independent of any LLM judge. Add abstention as a first-class monitored metric and gate config/model changes through per-domain golden evals.

*Why:* HALO frames zero-hallucination as a system property via independent layers and deterministic evidence-based confidence; RAGAL shows retrieval engineering + retriever fine-tuning and structural anti-hallucination (anchor distillation) beat bigger generators and that per-domain evals prevent silent regressions; Beyond-Relevance shows reusing evaluation rubrics as a selection signal shrinks context while improving answer quality. Together they specify a buildable, trustworthy RAG stack.
*Sources:* [[zero-hallucination-by-construction-hallucination-aware-layered-oversight-for-trustworthy-enterprise-ai]], [[ragal-a-frugal-fully-local-retrieval-augmented-assistant-for-technical-support-at-a-government-agency]], [[beyond-relevance-centric-retrieval-rubric-oriented-document-set-selection-and-ranking]]

### A cost-aware small-large model routing layer for coding/reasoning workloads
Build a serving layer that runs a self-hosted small model first and, mid-generation, hands off partial reasoning to a frontier API via a single control token, with the routing policy trained directly against billed cost (prefill+decode priced separately). Combine it with hidden-state-based tool-output pruning for open-weight coding agents so long multi-turn contexts stay cheap. Expose a single lambda knob to pick accuracy-cost operating points.

*Why:* PyroDash trains an SLM to emit a handoff token optimized against real billed cost, beating routing baselines at up to 96.4% cost reduction; SWE-Pruner Pro shows the coder backbone's own hidden states already encode which tool-output lines to prune, cutting up to 39% of tokens with ~15% overhead. Both are complementary, practical cost levers for anyone self-hosting an SLM alongside a proprietary API.
*Sources:* [[pyrodash-cost-efficient-token-level-small-large-language-model-collaborative-inference]], [[swe-pruner-pro-the-coder-llm-already-knows-what-to-prune]]

### A pre-deployment diagnostic for test-time collaboration and prompt scaling
Build a tooling library that, before you add a critic/verifier/multi-agent selector or a large multi-instruction prompt, runs a small labeled audit: estimate the oracle gap (recoverable mass) of the candidate pool, measure a signal's coverage/fidelity(MCC)/harm rate, and empirically test format, instruction-count, and prompt placement on your specific model. It outputs a go/no-go recommendation (e.g. 'pool is homogeneous, a selector will net-harm; split instructions past N=40').

*Why:* OracleGap shows collaboration gains come from high-fidelity low-harm signals over pools with recoverable mass, not agent count/topology, and that LLM selectors are often net-negative on homogeneous pools. Prompt Design at Scale shows no format wins consistently, adherence floors by N=80, placement effects are model-specific, and refusal is the real long-context failure. A diagnostic that operationalizes these findings prevents wasted compute and misguided prompt engineering.
*Sources:* [[oracle-gap-and-signal-fidelity-a-fixed-pool-diagnostic-for-test-time-collaboration]], [[prompt-design-at-scale-how-format-instruction-count-and-context-length-shape-instruction-adherence-and-hallucination-in-large-language-models]]
