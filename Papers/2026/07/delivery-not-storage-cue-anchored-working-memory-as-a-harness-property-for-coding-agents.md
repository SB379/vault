# Delivery, Not Storage: Cue-Anchored Working Memory as a Harness Property for Coding Agents

## TL;DR
The paper argues that agent memory is a delivery (control-plane) problem, not a storage (content-plane) problem: agents almost never voluntarily use memory tools even when a store is pre-seeded with task-relevant facts, so the harness itself must deterministically inject cue-anchored memories at structured moments (session start, prompt submit, pre-edit, pre/post-compaction). A controlled coding-agent evaluation plus a forced-compaction decay probe show that harness-owned injection delivers facts reliably (139/139 deliveries through 138 compactions) while conversation-held facts vanish at the very first summary boundary.

## Abstract
> Coding agents ship with one kind of memory: documents. Instruction files, plan artifacts, and auto-written memory directories are deliberately authored and deliberately retrieved: the agent must choose to write them and choose to read them back. Human expertise runs on a second tier that never gets written down: situationally-bound operational facts (gotchas, locations, local conventions) encoded as a side effect of the work and retrieved involuntarily when the situation cues them. We argue this second tier is the load-bearing one for long-running agents and must be a harness property, not an agent choice. We contribute: (1) a two-tier design theory grounded in the cognitive literature on memory offloading, incidental encoding, and event-based prospective memory, each mapped to an architectural requirement; (2) a cue-anchored memory model where memories carry first-class trigger conditions over a composable vocabulary (path, symbol, semantic, event, temporal), evaluated deterministically by the harness, a composition no surveyed academic or shipped system provides; (3) a controlled evaluation on a real coding task showing that voluntary memory use is near zero even with a pre-seeded store (0 memory operations in 114 turns), that deterministic injection delivered in every seeded run with zero false alarms, and that 39% of intra-session re-reads re-buy content paid for before a compaction boundary; (4) a repeated-compaction decay probe: ten facts held only in conversation vanish at the first summary and stay absent from 106 of 108 compactions, and the deprived agent greps the harness's own session files to rebuild them, while the same facts injected from a harness-owned store arrive intact through all 138 compact-resumes as the final summary carries none. Delivery, not storage, is the product: the reliable memory channel for agents is the one the agent never has to think about.

## Highlights
- Voluntary memory use rounds to zero: a seeded-voluntary agent made 0 memory calls across 114 turns despite task-relevant seeded notes, connected tools, and 32 guidance mentions; unseeded equipped runs made 0-1 writes.
- Deterministic injection worked across two independent channels (native hooks and API proxy) with zero false-alarm fires across 40 and 35 audit-logged trigger evaluations; cue-anchored gotcha fired on first touch of the anchored file and was deduped by a per-session fire ledger that resets at compaction.
- 39% (24 of 61) of intra-session re-reads re-retrieved content already read before a compaction boundary; the worst run re-paid ~31.6k tokens (about a sixth of a context window).
- Decay probe: conversation-only facts (arm N) dropped at the first summary and were absent in 106 of 108 boundaries; the deprived agent resorted to grepping the harness's own session JSONL files (260 shell commands, banned) to reconstruct them.
- Injected store (arm M) delivered all ten facts through 138 compactions — 139 audit-logged deliveries (launch + 138/138 compact-resumes) — while the final continuation summary carried 0/10, proving the endpoint never depended on the summarizer.
- Summarizer selection is all-or-nothing and unreliable independent of fact availability: even with facts injected into the summarized context, summaries were bimodal (0/10 or 10/10), never a strict subset; a re-surfaced fact block survived only ~1 further summarization pass.
- Second-order findings: unseeded task state decayed into confabulation (invented 'Phase 52: Files 203-206' in a 16-phase audit), summaries propagated the false task model, and the harness's autocompact thrash guard actively fought the memory-carrying configuration (forced M to a 6k read cap vs N's 8k).
- No correctness harm: 12/12 graded runs passed the fingerprinted acceptance test and regression suite; injection also 'begets engagement' — the only voluntary memory operations observed came after deterministic delivery.

## Method
The authors ground a two-tier memory theory in cognitive literature (incidental encoding, cue-driven/involuntary retrieval, extended-mind endorsement criteria, episodic/semantic splits), mapping each mechanism to an architectural requirement. They specify a cue-anchored memory model where each memory is a tuple (content, kind, triggers, scope, decay); kinds are directive/gotcha/finding/task/reference, and triggers compose a vocabulary of {path (glob), symbol (code symbol graph), semantic (similarity floor), event (session start, prompt submit, pre-edit, pre-run, pre/post-compaction), temporal (not-before, cooldown)} with conjunction within a trigger and disjunction across triggers. Triggers are evaluated deterministically harness-side (no model in the delivery path), with budgeted two-tier injection (compact index by default, full content on demand/for cue fires), a per-session fire ledger that dedups and resets at compaction boundaries, provenance framing ('recorded by an AI session, not human-endorsed — verify'), and staleness checks against ground truth. Implemented in Vectr (an open-source local-first code-indexing daemon) integrated with Claude Code via two channels: native lifecycle hooks and a transparent API proxy. Evaluation runs a real feature task (implement reverse for the stream-mode Resequencer EIP) on a pinned Apache Camel checkout (~169k chunks) with Claude Sonnet 5, gated by an unmodified acceptance test plus 42 resequencer regression tests. Arms vary memory surface and delivery (none, cold store+tools, proxy, seeded proxy, native hooks, seeded voluntary). A separate decay probe uses Claude Haiku 4.5 driven through continuous compaction (100k window) over a 64-file audit, presenting ten synthetic facts once in a fixture file that is then deleted (defeating post-compaction file restoration), grading token-level survival in every summary and the final report plus provenance forensics over transcripts and the daemon audit ledger.

## Evals & Results
Twelve graded matrix runs (9 pilot + 3 native) plus one gated run per decay arm (N and M). Baselines: vanilla (no memory), tool-equipped-but-cold store, voluntary tools, and seeded-voluntary control. All 12 graded runs passed acceptance + regression (no correctness harm). Count-based platform metrics (tool-surface effect, mostly cold store) showed vanilla vs tool-equipped: total tool calls 137.3 vs 79.8 (-42%), grep/find 48.3 vs 22.2 (-54%), cost $7.20 vs $5.08 (-30%), turns 106.3 vs 77.0 (-28%). Knowledge-held-constant memory comparison: both hook runs (H1: 95 turns/$5.22; H2: 102 turns/$6.09) beat voluntary (V1: 114 turns/$6.23) and beat the proxy pilot (CS: 106 turns/$6.57). The authors explicitly label all efficiency signals directional (n too small, within-arm wall spreads 2.4-4.4x; ~15-20 runs/arm needed for significance). Decay probe endpoints both scored 10/10 but arm N's is invalidated by forensics (transcript archaeology), while arm M's is clean (injection-sourced, final summary 0/10). Mid-run availability — the operative metric — differs sharply: N carried 0/10 at 106 of 108 boundaries; M received all ten at every one of 138. Cost of the memory tier: M was +21% turns and +36% cost vs N, partly confounded by the forced 6k read cap and confabulation spiral. Audit completeness (declaration recall vs regex ground truth) was 0.70 (M) vs 0.93 (N), confounded by M's tighter read cap. Motivating prior work: MEMTRACK (memory-utilization failure) and TriggerBench (prospective > retrospective difficulty, decaying with context length) are replicated naturalistically.

## So What (for practitioners)
Do not rely on agents voluntarily reading or writing memory — voluntary usage is effectively zero even with a seeded, well-guided store, so memory must be a harness/control-plane feature that deterministically decides what enters the context window and when. Build memory as delivery: attach standing per-item trigger conditions (path/symbol/semantic/event/temporal) and inject at lifecycle events, especially session start and every post-compaction resume, rather than depending on the summarizer to retain facts (it drops them all-or-nothing and unreliably even when they are in-context at summarization time). Treat compaction boundaries as where re-exploration waste concentrates and target them with deterministic re-injection. Add operational discipline: per-session fire ledger to dedup (reset at compaction), budgeted two-tier injection where each fact must ride the index line itself (index titles don't travel), staleness checks against ground truth, and provenance framing so injected memory reads as verifiable rather than authoritative. Keep the delivery path deterministic and fully audit-logged for auditability. Be aware that harness features tuned for memoryless operation (e.g., autocompact thrash guards) can actively penalize memory-carrying configurations by reading fixed per-cycle context (tool schemas, guidance, injections) as refill pressure. Injecting memory also begets voluntary engagement (recall/forget/remember hygiene loops), so delivery seeds good behavior rather than replacing it.

## Open Questions / Critiques
The evaluation is very small (12 graded runs; one gated run per decay arm after documented protocol repairs) and explicitly directional, not a population estimate — no effect-size claims survive scrutiny. Author conflict: the evaluated system and benchmark harness share an author (mitigated by pinned corpus SHA, fingerprinted test, published transcripts/graders). Narrow external validity: one corpus (Apache Camel, present in training data, shrinking the exploration burden), one task family, one agent product, one model family; the decay probe uses a small fast model (Haiku 4.5) whose summarization behavior may not generalize to larger summarizers, and a pinned 100k window that halves per-boundary content pressure. Capture is entirely unevaluated — all facts were hand-seeded by the harness, so the paper measures delivery and survival, not whether incidental automatic encoding actually works (the theory's 'open half'). The trigger composition claim rests on only 3 of 5 vocabulary elements (path, event, semantic) actually firing; symbol and temporal were implemented but never fired. Fact survival is verbatim token-match, potentially missing paraphrased survival. Tool bans (no shell, no subagents) were unenforceable under context loss in both decay arms. The unexplained bimodal regime change in arm M's survival curve (72 consecutive later summaries carrying 0/10 despite on-schedule deliveries) is acknowledged as not fully understood. Cost overhead (+21% turns, +36% cost) and the harness thrash-guard conflict are real production frictions that the paper surfaces but does not resolve, and stale-memory poisoning defenses are cited as insufficient without a demonstrated mitigation.
