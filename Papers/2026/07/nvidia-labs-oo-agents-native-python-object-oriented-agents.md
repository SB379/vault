# NVIDIA-labs OO Agents: Native Python Object-Oriented Agents

## TL;DR
NOOA (NVIDIA Object-Oriented Agents) is a model-agnostic Python framework where an agent is a plain Python object: methods are actions, fields are state, docstrings are prompts, type annotations are contracts, and methods with an ellipsis (...) body become LLM-driven loops. It combines six model-facing capabilities (typed I/O, pass-by-reference, code-as-action, loop engineering, object state, model-callable harness APIs) on one surface and shows current models use it zero-shot, matching or beating open harnesses on SWE-bench Verified, Terminal-Bench 2.0, CyberGym, and ARC-AGI-3 at lower token cost.

## Abstract
> Traditional agent development is split across prompt templates, tool schemas, callback code, and workflow graphs. We present NVIDIA Object-Oriented Agents (NOOA), a model-agnostic Python framework for building reliable AI agents. NOOA takes a simpler approach: an agent is a Python object. Its methods are the actions the model can take, fields are its state, docstrings are its prompts, and its type annotations are contracts. A method whose code body consists of "..." is completed at runtime by an LLM-driven agent loop, while methods with normal bodies remain standard deterministic Python. This gives developers and agents the same interface, so agent behavior can be tested, traced, refactored, and improved just like other software. This paper makes three contributions. (1) We present the agent-as-a-Python-object programming model and the design principles behind it. Where Python has existing abstractions, we adopt them directly. Agent-specific capabilities--context, events, state rendering, long-term memory, and validated LLM loops--are exposed through simple Pythonic APIs, so both developers and agents share one familiar programming model. (2) We identify six model-facing ideas that NOOA is, to our knowledge, the first to combine on a single surface: typed input/output, pass-by-reference over live objects, code as action, programmable loop engineering, explicit object state, and model-callable harness APIs for context and events. We find the community already converging on several of these ideas--often as experimental or partial features--and present the comparison to encourage further adoption. (3) We demonstrate that current models use this interface effectively, both in targeted capability tests and on agentic and reasoning benchmarks such as SWE-bench Verified and Terminal-Bench 2.0 and ARC-AGI-3.

## Highlights
- Capability suite: 97.9% pass (4309/4400 records) across 10 models; frontier models 99.2%, small/efficient 96.0%; GPT-5.5 perfect. Residual failures cluster in 6 'stress' families (84.7%) — disciplined multi-step use, not interface comprehension.
- SWE-bench Verified: NOOA highest among open harnesses in every config — 82.2% (GPT-5.5 xhigh) and 79.8% (Opus 4.6), beating OpenCode (78.6%) and PI (78.2%); +11.4 pts over OpenHands v3 CodeAct on Opus. Specialized closed systems: Codex 88.7%, Claude Code 80.8%.
- Terminal-Bench 2.0: larger lead — 46.1% vs 34.8/37.1% (GPT-5.5, reasoning off); 73.0% at high effort; Opus 4.6 65.2% comparable to Claude Code/Terminus-2 (62.9–65.4%).
- Token efficiency: SWE-bench GPT-5.5 xhigh reaches 82.2% with ~28 calls / 1.1M tokens/task vs PI's 66 calls / 2.2M tokens for 78.2% — pass-by-reference keeps tool outputs as live variables instead of re-serializing them.
- CyberGym L1: 86.8% solve rate (GPT-5.5, network blocked) — top open-source agent, beating most closed systems; baseline Codex was 64.9%.
- ARC-AGI-3: one NOOA agent + 50-line skill replaced the 6-agent DreamTeam system; RHAE 50.2% (GPT-5.5) and 85.1% (GPT-5.6-sol) at <$20/game; memory subsystem gave +11.8 pts over identical agent with markdown files. Raw GPT-5.6-sol scores 13.3% → 6.4x harness effect.
- NOOA is the only one of 15 surveyed frameworks (LangGraph, Deep Agents, MS Agent Framework, OpenAI Agents SDK, ADK, PydanticAI, smolagents, Claude SDK, Codex, OpenHands, PI, Hermes, OpenCode, OpenClaw) to natively expose all six interface capabilities.

## Method
An agent is a single Python class subclassing Agent. Ordinary methods run as deterministic Python and are callable by the model; methods whose body is `...` become 'agentic methods' executed via a per-method @strategy decorator. Two built-in strategies: PredictStrategy (single typed LLM call with local retry on type-validation failure) and CodeActStrategy (an iterative Jupyter-like REPL where the model calls execute_python(...) to compute/inspect/call helpers/spawn subagents, then return_result(...) which is type-validated). The CodeAct loop per turn: render context → call LLM → execute Python cell in a restricted session (rejecting eval/exec/compile/input/blocking calls) → append typed events → validate return. Context has three regions for KV-cache reuse: a stable static prefix (system prompt ~1k chars, strategy instructions ~2.5k, execution context, doc(self)), an append-only typed event history (queryable, collapsible into summaries à la MemGPT), and a trailing dynamic context block re-rendered each turn (pprint(self), TODO lists, etc.). Pass-by-reference: method args are live Python objects; the model sees only a bounded preview (type, true length, head/tail sample) e.g. `records = list(len=100, [:5]=[...], [-5:]=[...])` while the full object stays bound as a local — data volume is bounded by the execution environment, not the context window. Media args render as native multimodal blocks. An optional MemoryManager.install(agent) adds long-term memory: seven model-callable tools (remember/recall/search/update_memory/forget/associate/deref) over a single inspectable SQLite file with a derived vector index; retrieval unions embedding+keyword candidates ranked by ACT-R activation (relevance/recency/importance) over a typed memory graph; spontaneous BeforeTurn injection (touch=False so it doesn't self-reinforce); asynchronous reflection consolidates/merges/prunes. Memories can hold kind:key references resolved against live state at recall.

## Evals & Results
Four benchmarks. (1) SWE-bench Verified (500 real GitHub issue tasks) and (2) Terminal-Bench 2.0 (89 CLI tasks) used a single 253-line benchmark-agnostic 'BenchAgent' with todo list, shell/file tools, and tree-sitter navigation, terminating via a validated typed TaskResult (root cause + evidence + verification command). Baselines: OpenCode and PI (minimal), all on GPT-5.5 and Opus 4.6 at matched reasoning-effort. NOOA led open harnesses in every config and defined most of the accuracy–cost Pareto frontier; key mechanism is 'validated termination' (77% of OpenCode's failed Terminal-Bench trials terminated within 10 steps by responding without a tool call, whereas NOOA requires a validated result). Advantage is largest when reasoning is off, narrowing at higher effort. (3) CyberGym L1 (find+PoC software vulnerabilities): 86.8% with a rule-based cheat-check confirming no network lookups. (4) ARC-AGI-3 interactive reasoning: 25-game fleets; a world-model skill (encode→latent, predict dynamics, retrodiction as refinement signal, search) with memory beat a hypothesis baseline (+8.5) and a markdown-file ablation (+11.8 RHAE). Layered sandboxing (per-cell Landlock/seccomp, uid drop, alias anonymization) passed an 18-pass red-team audit with zero leakage.

## So What (for practitioners)
If your team already knows Python, NOOA collapses prompts/schemas/tools/orchestration into one testable, traceable, refactorable class — reducing framework-specific learning and leaning on code already in model training data. Two techniques generalize even outside NOOA: (a) pass-by-reference / bounded previews — keep large tool outputs as live variables and only print what you need, saving tokens (roughly 2x fewer calls/tokens here) and preserving prefix-cache reuse instead of lossy transcript compaction; (b) validated typed termination — make 'done' a programmatically checked action (evidence + verification command) rather than an informal prompt convention, which materially reduces premature/unsupported completions. Route cheap classification methods to small models and open-ended ones to a larger model per method. Structure context into static prefix / append-only events / trailing dynamic block to maximize KV-cache reuse. For long-horizon agents, an agent-curated typed memory store (importance/recency scored, bounded injection) outperformed plain markdown notes. Be aware NOOA runs model code in-process, so sandbox the whole process (container/VM) exactly as you would for any shell-tool agent.

## Open Questions / Critiques
In-process execution means the code validator protects the agent loop, not the host — safety depends on external sandboxing, and the paper notes a known cell-guard AST-evasion gap (backstopped by uid drop). Reasoning-effort analysis suggests NOOA's advantages partly substitute for planning discipline that stronger models increasingly do themselves, so margins may shrink as base models improve. The main residual failures are 'disciplined multi-step use' (e.g., Opus retyping a computed list and dropping an item instead of returning the variable; GPT-5.4 Mini using keyword rules on unseen items) — reliability, not comprehension, and they are only hypothetically addressable via trajectory-level RL (future work). Benchmarks use frontier models (GPT-5.5/5.6-sol, Opus 4.6) not broadly available; some comparison-harness capabilities were scored from docs/source at pinned snapshots and may be uncharitable. ARC-AGI-3 numbers are n=25 with 16 outcomes right-censored, making memory-performance links associational; the dramatic 6.4x harness effect uses differing evaluation budgets ('indicative'). No standard truncation-preview format exists yet, and RL over the harness action space remains unvalidated.
