# Beyond Relevance-Centric Retrieval: Rubric-Oriented Document Set Selection and Ranking

## TL;DR
The paper argues that relevance-only retrieval evaluation (nDCG) ignores inter-document interactions like redundancy, conflict, and complementarity that determine RAG quality. It introduces SetwiseEvalKit (a 3-level, 9-dimension, ~28K-rubric benchmark) plus Rubric4Setwise, a training-free method that reuses evaluation rubrics as document-set selection signals, achieving better downstream generation with fewer documents and search rounds.

## Abstract
> As large language models and AI agents become the primary consumers of search results, document set quality determines the upper bound of downstream generation. Yet existing evaluation systems remain confined to scoring documents independently and aggregating via nDCG, ignoring inter-document interactions (redundancy, conflict, complementarity) and unable to answer what makes one document set better than another. To address these issues, we propose a complete evaluate-diagnose-optimize framework. We design SetwiseEvalKit, a three-level, nine-dimension document set evaluation benchmark covering both short-form and long-form scenarios, comprising approximately 28K high-quality evaluation rubrics. We systematically evaluate 12 rerankers: even the best method achieves no more than 45% coverage, cross-document coordination dimensions are universally weak, and no single method maintains top performance across both settings. Building on this, we propose Rubric4Setwise, a training-free method that converts rubric-based evaluation criteria into document set selection signals, achieving the best downstream generation performance with fewer documents and search rounds. It is the only method that maintains state-of-the-art results across both scenarios, validating the effectiveness of closing the loop from evaluation to optimization.

## Highlights
- Existing rerankers are universally weak: even the best method achieves \u226445% overall rubric coverage, with cross-document coordination dimensions (Complementarity, Completeness) being the biggest bottleneck.
- Rubric coverage scores correlate strongly with downstream generation quality (Pearson r=0.92, p=0.0013), validating the benchmark as predictive of real RAG performance.
- Rubric4Setwise achieves best short-form results (EM 26.10, F1 29.32) using only 2.66 documents on average vs fixed top-5 baselines, and best long-form LLM-judge score (70.57) with fewer documents (20.52 vs 29.23) and fewer rounds (4.52 vs 4.73) than second-best SetR.
- No single reranker generalizes across settings: Setwise methods (SetR, Rank4Gen) dominate short-form multi-hop QA, while reasoning-enhanced methods (ReasonRank, Rearank) lead long-form deep-research scenarios.
- In long-form multi-turn search, rubric scores degrade monotonically across rounds (early broad acquisition -> later narrow gap-filling); union scoring after deduplication is used for fair evaluation. Reachability stays extremely low (4.38-11.60) across all methods.
- Conflict scores are uniformly high with low variance, indicating factual contradiction is not the main bottleneck in these datasets; set-level dimensions show narrow reranker separation (weak, non-significant correlations due to homogeneity).
- Multi-model rubric generation + aggregation improves quality: ~70% of DeepSeek-aggregated rubrics judged highly/critically discriminative vs 37% (GPT 5.1) and 43% (Gemini), with only ~8% waste rate.

## Method
Task: given query q and reference answer a, generate query-specific rubrics R covering nine quality dimensions across three levels: Doc-level (Relevance, Authenticity, Quality), Set-level (Complementarity, Redundancy, Conflict), Global-level (Completeness, Density, Reachability). An LLM judge scores a selected document set as a whole (0-4 per rubric) instead of scoring documents independently and aggregating via nDCG. Coverage% per dimension = mean rubric score / 4 * 100. Data: short-form from 4 multi-hop QA datasets (HotpotQA, 2WikiMultihopQA, MuSiQue, Bamboogle; 2061 samples, BM25 top-20 candidate pool); long-form from 200 ResearchQA instances using the DR.Tulu-8B search agent with rerankers wrapped as MCP tools applied after each retrieval turn. Rubrics generated by GPT 5.1 and Gemini 3.1-Pro-Preview independently, then aggregated/filtered by DeepSeek-V4 Pro (~24K short-form, ~4K long-form; ~28K total). Judge = DeepSeek-V4 Pro scoring all dimensions in one pass, with a relevance gating mechanism (if all docs score 0 on relevance, only relevance is reported) and two independent scoring passes for stability. Rubric4Setwise uses Qwen3-8B as a chain-of-thought reasoning backbone: it maps each rubric to satisfying passages, then selects the minimum set covering all rubric items (adaptive set size), implicitly modeling a rubric-based set utility function without training. Note: rubrics are generated using reference answers (oracle setting).

## Evals & Results
Benchmarks: SetwiseEvalKit short-form (multi-hop QA, EM/F1 with Llama-3.1-8B-Instruct generator) and long-form (ResearchQA, LLM-judge with DR.Tulu-8B agent). 12 rerankers evaluated across three families: Adhoc (BGE-Reranker-Large, MonoT5-3B, RankT5, RankLlama-7B, RankVicuna, RankZephyr, Setwise), Reasoning-enhanced (Rank1, Rearank, ReasonRank), and Setwise (SetR-8B, Rank4Gen-8B), plus raw BM25/Google Search lower bounds. On rubric coverage: SetR led short-form overall (45.85%), Rank4Gen second (43.87%); ReasonRank led long-form (33.05%). Downstream generation: Rubric4Setwise best on both (short-form EM 26.10/F1 29.32 with 2.66 docs; long-form LLM-judge 70.57 with 20.52 docs, 4.52 rounds), beating SetR by ~0.97 EM. Reproducibility: doc-level dimensions most stable (Kendall tau >=0.74, Pearson r=1.00 short-form; item-level Cohen kappa 0.77-0.94); Density and Conflict have fragile ordering due to narrow reranker separation. Human study inter-annotator agreement: Krippendorff alpha=0.81, ICC=0.84.

## So What (for practitioners)
Stop treating retrieved set quality as the sum of per-document relevance; nDCG can be 100% while the set is redundant, conflicting, or missing a reasoning link. If you already run rubric-based LLM-as-judge evaluation for RAG, you can reuse those same rubrics as an active selection signal (prompt an LLM to pick the minimal passage set that satisfies all rubric items) to shrink context and reduce search rounds while improving answer quality. Evaluate rerankers with multi-dimensional, set-level rubrics and per-slice breakdowns rather than a single aggregate, since no reranker is best across single-turn and multi-turn agent scenarios. For multi-turn deep-research agents, evaluate the deduplicated union of documents across rounds (per-round scores drop naturally as retrieval shifts to gap-filling), and know that assembling sets that support full end-to-end reasoning chains (Reachability) is the dominant unsolved bottleneck. Use multi-model rubric generation plus an aggregation/filtering pass to get discriminative, low-waste rubrics.

## Open Questions / Critiques
The biggest caveat is the oracle setting: rubrics are generated using the gold/reference answer, so Rubric4Setwise's reported gains are an empirical upper bound not achievable in production where no reference answer exists (the authors flag distilling rubric preferences into reference-free rewards as future work). The judge, rubric aggregator, and rubric generators are all frontier proprietary models (DeepSeek-V4 Pro, GPT 5.1, Gemini 3.1-Pro-Preview labeled with future-dated version names), raising cost, reproducibility, and potential self-preference concerns; the entire evaluation is LLM-judge-based rather than grounded in independent ground truth. The r=0.92 credibility correlation is computed over only ~12 reranker points. Set-level dimensions (Complementarity, Conflict) show near-zero variance across current rerankers, so the benchmark cannot yet discriminate methods on precisely the interactions it was built to measure. Long-form scoring is noisier (6-20pt drops in stability), and the downstream long-form gains are small (~2-3 LLM-judge points). Generalization beyond Wikipedia multi-hop QA and ResearchQA, and the added inference cost of rubric generation + set selection, remain untested.
