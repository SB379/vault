# Decode-Time Grammars: Constrained LLM Generation over a Refinement Order of Grammar Fragments

## TL;DR
Decode-time grammars instantiate grammar fragments during generation from a live runtime environment Γ (declared names, schema columns, API surfaces, tool state), so reference positions become Γ-typed slots whose candidates are exactly what exists at that point. This removes 'ghost references' (syntactically valid but environment-invalid names) from the decoder's support set by construction, rather than merely making them unlikely, at ~10–18% serving overhead over standard constrained decoding.

## Abstract
> Large language models now write a growing share of the world's code, increasingly inside agents and serving systems that compile, execute, or dispatch generated code without line-by-line review. This works well for mainstream languages but remains brittle for low-resource programming surfaces such as domain-specific languages, custom library APIs, and command-line tools. Even under grammar-constrained decoding, a model can still produce references invalid in the current environment: a buffer never declared, a column absent from the schema, a function the library does not provide, or an unsupported CLI option. This paper introduces decode-time grammars: grammar fragments instantiated during generation from a runtime environment Gamma. A region-specific policy selects a fragment for each hole, and a tightening operator replaces open reference positions with Gamma-typed slots whose candidates are exactly the names, fields, APIs, or options available at that point. Newly generated declarations enter Gamma before later regions are decoded, so the constraining grammar can depend on the prefix already generated. This ensures not only grammatical correctness but also semantic correctness, by preventing references to undefined symbols. We formalize grammar fragments as environment-indexed grammars ordered by refinement, prove No-Ghost soundness for Gamma-slotted fragments, show that refinement preserves this support-set guarantee, and characterize the boundary of mask-enforceable properties. We implement the approach in gproj with offline grammar induction and online policy resolution. Across TileLang, SQL, and P4, with models from 0.6B to 236B parameters, gproj eliminates ghost references by construction at moderate overhead over standard constrained decoding.

## Highlights
- Ghost references arise mainly from negative transfer (e.g. DeepSeek-V4-Flash reaching for TVMScript's T.Buffer instead of TileLang's T.Tensor), so they persist even as models get stronger — a mask-side fix removes them regardless of model probability.
- On Spider SQL, constraining the column position to the selected table's schema raised execution-match from 76% (unconstrained) to 100%, while remaining ghost-free by construction; open-identifier columns produced ghosts in 90/90 samples (0% exec-match).
- Across TileLang/SQL/P4 and models from 0.6B to 236B, every Γ-typed arm was ghost-free by construction while every free-identifier arm failed via ghost references (e.g. TileLang open operands = 0% compilation across 0.6B/20B/27B/120B, all failures being ghost-name NameErrors).
- On the TileLang GEMM 'cliff', loosening only operand fragments moved compilation 100%→100%→67%→0% while free_bits rose 92→287→538→998 — the collapse to 0% happens precisely when references leave Γ, not from increased freedom per se.
- Against cheaper alternatives on 60 Spider samples: prompt-schema hit 93.3% (4 ghosts), retry (k≤4) hit 90.0% (5 ghosts, 40 tokens avg), but the Γ-typed mask hit 100% with 0 ghosts in one pass at 6.6 tokens avg.
- Serving overhead: gproj reduces throughput 10.6–17.8% vs XGrammar (14% avg) and 17.3% avg vs unconstrained decoding.
- Theoretical necessity result (Prop. 3): no finite family of precompiled fixed-support grammars can be both sound (no undeclared names) and non-blocking over an unbounded identifier space — exact reference support must be synthesized from the prefix at decode time.

## Method
They formalize 'grammar fragments' as environment-indexed grammars projecting into a shared many-sorted semantic domain, ordered by a refinement preorder ⊑. The core operator τ_Γ replaces an open reference position (e.g. buffer::=identifier) with a Γ-typed slot whose candidate set is queried from the live environment (e.g. Γ.names(sort=Buffer, mem=shared)) and rendered as an escaped, parenthesized alternation spliced into the production. Two systems implement this: (1) gproj, an online masked executor that decodes a skeleton grammar as nested sort-anchored region-holes via a grammar-call stack; on completing a declaration hole it extracts declared names and extends Γ before later holes are instantiated (self-extending grammar), maintaining lexical scope frames with write-once bindings; (2) TemplateInductor, an offline inductor that builds four-rung refinement ladders (base→gamma→ctx→pin) from small corpora using anti-unification to find skeletons plus variation points, an LLM to decide which positions are Γ-dependent, and a 'hard gate' that validates candidate GBNF fragments against the same engine used online (accepting corpus positives, rejecting auto-mined ghost substitutions). Key proofs: an Escaping Lemma (parenthesization prevents |-split leaks), No-Ghost single-hole soundness (Theorem 1, modulo an empirically differential-tested engine-correspondence assumption), refinement preserving soundness (Lemma 2, so switching rungs never re-admits a ghost), and a whole-program corollary. A per-region policy π(s,Γ) selects fragment strength, with graceful fallback to coarser rungs when a slot query returns no candidates. Built on XGrammar-style JIT masking; the grammar-call stack, runtime-Γ instantiation, declaration extraction and frame overlays live in the executor, not the engine.

## Evals & Results
Surfaces: TileLang (compile + torch numerical oracle), SQL/Spider (execution-match), P4 (p4c compiler), plus library APIs (AVX-512 intrinsics, FFmpeg, a private pandas-like table API, Huawei CANN ops-nn, jq, CMake) and CLI tools (git, make, npm). Models: Qwen3-0.6B (primary), gpt-oss-20B, Qwen3.5-27B-distill, 120B Nemotron, 236B DeepSeek-V4-Flash. Baselines: free open-identifier, unconstrained decoding, prompt-with-schema, retry/self-repair, and XGrammar for overhead. What moved: SQL exec-match 76%→100% (and ladder 0%→85% at gamma→100% at gamma_table); TileLang/P4 compilation went from 0% (all ghost failures) to full compilation with zero ghosts under Γ-slots; git checkout picked real branches in 8/8 vs 8 invented; frontier model went from 8/8 wrong-dialect samples to real-API ghost-free programs (all GEMM + 7/8 elementwise also passing numerics). Adding shape attributes to GQA operand queries cut wrong-shape selection from 2.5% to 0% by construction. Offline induction recovered fragment families over CANN's 22 operator categories and reconstructed ladders on SQL/jq/TileLang. Compilation/numerical correctness remained oracle-checked, not guaranteed.

## So What (for practitioners)
For low-resource programming surfaces (DSLs, custom/version-specific library APIs, CLI tools) where generated code is executed without review, prompting/fine-tuning/retry only bias probabilities and cannot guarantee valid references — a support-set (masking) approach that enumerates legal names/columns/APIs/options from the actual environment eliminates that error class entirely and does so cheaply, independent of how strongly the model prefers a wrong (fluent) alternative like a neighboring dialect. Practically: (1) separate concerns — let the model own algorithm/query-intent/structure while the mask owns environment-bound references; (2) build a Γ source per surface (symbol table, DB schema introspection, compiler headers, tool self-description/live state) and re-instantiate slots per hole so declared names become candidates for later positions; (3) use graded fallback so absent candidates degrade gracefully rather than deadlock, and the empty-query event is itself an early diagnostic that the sketch omitted a declaration; (4) masking beats retry when the tool gives no error signal (e.g. CMake silently expands misspelled vars) since there's nothing to repair against. The mask handles mechanically enumerable errors; keep external oracles for functional/numerical/protocol correctness.

## Open Questions / Critiques
The guarantee is narrow: it only covers what's expressible as membership in Γ (P1 scope, P2 sort tags, P3 declaration-before-use at hole granularity, P4 write-once shape) — semantic value/numerical correctness, termination, call-order protocols, and mutable-attribute invariants (N1–N3) are explicitly out of scope and remain model responsibility. Theorem 1 holds only modulo Assumption 1 (engine–denotation correspondence), validated by differential testing on a small closed construct vocabulary rather than proven. Several offline-induction results (AscendC, jq) are evaluated only at parser/hard-gate level without end-to-end compilation because vendor compilers were unavailable. Coverage is skewed to reference-dense, declaration-scoped DSLs; the authors note general C++/Python need heap/alias/scheduling facts beyond name membership and regex has no environment to specialize. Engineering limits: the Times repetition combinator doesn't compose with nested grammar calls, recursion is capped, and finite token budgets can strand locally-legal prefixes. Reliance on a strong LLM for offline induction and on trusted declaration-extraction/frame-management (the 'environment fidelity' invariant) is assumed rather than independently verified. Some sample sizes are small (n=8–20 for TileLang/P4/CLI/GQA), and the paper cites future-dated references (2026), so treat as a preprint-stage result.
